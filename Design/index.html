    CogniAgents: Config-Driven Agentic Framework¶

    1. Overview¶

    CogniAgents is a generic, config-driven agentic framework built on:

    • PydanticAI for typed, structured LLM agents
    • An OpenAI-compatible endpoint (e.g., OpenWebUI) as the model backend
    • A flexible config.yaml to declare agents, workflows, and templates

    The framework is not limited to news aggregation. It’s designed to support many AI workflows, such as:

    • Document & email summarization
    • Trend, risk, or sentiment analysis
    • Data extraction & normalization
    • Code review & explanation
    • Content generation (blog posts, reports, social posts)
    • Internal tools (ticket triage, routing, classification)

    The core idea: you describe what agents exist and how workflows are composed in config.yaml. CogniAgents turns that into an executable pipeline using PydanticAI and your OpenWebUI models.

    2. Goals and Non-Goals¶

    2.1 Goals¶

    1. Generic: Support arbitrary domains (news, finance, code, customer service, etc.).
    2. Config-driven:
    3. Agents, prompts, models, and workflows live in config.yaml.
    4. Minimal code changes when you add or modify behavior.
    5. OpenWebUI-compatible:
    6. Talk to any OpenAI-compatible API (OpenWebUI) via OPENAI_BASE_URL / OPENAI_API_KEY.
    7. Typed with PydanticAI:
    8. Structured outputs where needed (Pydantic models).
    9. Plain strings where simple outputs are enough.
    10. Compositional workflows:
    11. Chain multiple agents in a configurable workflow (sequential or parallel).
    12. Extensible:
    13. Easy to add new agents, output schemas, and workflows.

    2.2 Non-Goals (v1)¶

    • Full autonomous planning / tool-calling orchestration (ReAct, etc.).
    • Long-term memory and retrieval-augmented generation.
    • Multi-tenant management (per-tenant configs) – can be added later.
    • Production UI for editing config (future enhancement).

    3. High-Level Architecture¶

    3.1 Core Concepts¶

    • Agent: A PydanticAI Agent with:
    • name, description
    • model (OpenWebUI model name)
    • instructions/prompt
    • output type (str or a Pydantic model)
    • Workflow: A named, ordered set of agents plus wiring rules:
    • Which agents run
    • In what order
    • How their outputs are aggregated into a final result
    • Template (optional): A Jinja2 template that turns workflow outputs into a final string (HTML, Markdown, JSON, etc.).

    3.2 Components¶

    1. Config Loader
    2. Loads config.yaml.
    3. Validates shape via Pydantic (optional but recommended).

    4. Exposes helpers:

      • get_global_llm_settings()
      • get_agent_configs()
      • get_workflow_configs()
      • get_templates()

    5. Agent Factory / Registry

    6. Converts config entries into CogniAgent instances (wrappers around PydanticAI agents).
    7. Keeps a cache of initialized agents.

    8. Ensures lazy or eager initialization based on runtime needs.

    9. CogniAgent (Wrapper)

    10. Encapsulates:
      • PydanticAI Agent
      • The configured output type (e.g., str, SummaryOutput, TrendAnalysisOutput)

    11. Provides:

      • async invoke(input: str, context: dict | None) -> Any

    12. Workflow Engine

    13. Reads workflow definition from config.
    14. For a workflow:
      • Resolves agent list.
      • Executes agents (sequential or parallel).
      • Manages enriched_data / context object passed between steps.

    15. Optionally renders a final output via a template.

    16. Rendering Layer

    17. Jinja2 (or similar) to render templates using:

      • Workflow outputs
      • Input payload metadata
      • Global or workflow-specific context

    18. LLM Service (OpenWebUI)

    19. OpenAI-compatible API at OPENAI_BASE_URL (e.g., http://openwebui:8080/v1).
    20. Model names (e.g., gemini-2.5-flash, buffettvision, code-reviewer) are treated as opaque strings and passed through as model in the OpenAI payload.

## 5. Config Design (`config.yaml`)

### 5.1 Top-Level Structure (Generic)

```yaml
global_llm_settings:
  model: "gemini-2.5-flash"
  temperature: 0.1

agents:
  - name: "generic_summarizer"
    title: "Generic Summarizer"
    description: "Summarizes any text content."
    llm_model: "gemini-2.5-flash"
    output_schema: "summary"     # optional hint: maps to a Pydantic model or str
    prompt: |
      Summarize the following content clearly and concisely.
      Do not refer to "this text" or "the document" in your answer.

  - name: "sentiment_analyzer"
    title: "Sentiment Analyzer"
    description: "Classifies sentiment of text."
    llm_model: "sentiment-model"
    output_schema: "sentiment"
    prompt: |
      Analyze the sentiment of the following content and return:
      - overall sentiment (positive, neutral, negative)
      - a short rationale.

  - name: "code_reviewer"
    title: "Code Reviewer"
    description: "Reviews code snippets."
    llm_model: "code-reviewer"
    output_schema: "code_review"
    prompt: |
      You are a senior engineer. Review the following code and provide:
      - key issues
      - suggested improvements
      - overall risk level.

workflows:
  - name: "summarize_document"
    description: "Summarize arbitrary input text."
    steps:
      - agent: "generic_summarizer"
        input_from: "payload.content"   # where to get input
        save_as: "summary"              # key in workflow context

  - name: "analyze_text_with_sentiment"
    description: "Summarize and analyze sentiment."
    steps:
      - agent: "generic_summarizer"
        input_from: "payload.content"
        save_as: "summary"
      - agent: "sentiment_analyzer"
        input_from: "payload.content"
        save_as: "sentiment"

  - name: "review_code_snippet"
    description: "Run code review on a snippet."
    steps:
      - agent: "code_reviewer"
        input_from: "payload.code"
        save_as: "review"

templates:
  # Example: generic HTML/Markdown templates keyed by workflow name
  summarize_document: |
    # Summary

    {{ summary }}

  analyze_text_with_sentiment: |
    # Summary

    {{ summary }}

    # Sentiment

    Overall sentiment: {{ sentiment.sentiment }}
    Rationale: {{ sentiment.rationale }}

defaults:
  # Default options that can be used by workflows/callers
  max_tokens: 2048
  language: "en"

    Note: output_schema is a logical name that the framework maps to:

    • str for simple text outputs, or
    • Pydantic models like SummaryOutput, SentimentOutput, CodeReviewOutput.

    6. Core Python Components¶

    6.1 Config Loader¶

    Responsibilities:

    • Load config.yaml once (with optional hot-reload in dev).
    • Provide typed accessors:
    def get_global_llm_settings() -> dict: ...
def get_agent_configs() -> list[dict]: ...
def get_workflow_configs() -> list[dict]: ...
def get_template(workflow_name: str) -> str | None: ...

    Optional: use Pydantic to validate config structure.

    6.2 Output Schemas (Pydantic Models)¶

    Example schema registry:

    from typing import Type, Dict, Union
from pydantic import BaseModel


class SummaryOutput(BaseModel):
    summary: str


class SentimentOutput(BaseModel):
    sentiment: str
    rationale: str


class CodeReviewOutput(BaseModel):
    issues: list[str]
    suggestions: list[str]
    risk_level: str


# Map logical schema names to actual Python types
OUTPUT_SCHEMAS: Dict[str, Type[BaseModel] | Type[str]] = {
    "summary": SummaryOutput,
    "sentiment": SentimentOutput,
    "code_review": CodeReviewOutput,
    # default: str if not present
}

    6.3 CogniAgent Wrapper¶

    import logging
from typing import Any, Dict, Type

from pydantic_ai import Agent as PydanticAIAgent
from pydantic_ai.models.openai import OpenAIChatModel

from .config_loader import get_global_llm_settings
from .schemas import OUTPUT_SCHEMAS  # mapping from output_schema -> type

logger = logging.getLogger(__name__)


class CogniAgent:
    def __init__(self, agent_config: Dict[str, Any]):
        self.name = agent_config["name"]
        self.title = agent_config.get("title", self.name)
        self.description = agent_config.get("description")
        self.prompt = agent_config["prompt"]
        self.llm_model = agent_config["llm_model"]
        self.temperature = agent_config.get("temperature")
        self.output_schema_name = agent_config.get("output_schema")

        global_llm = get_global_llm_settings()
        model_name = self.llm_model or global_llm.get("model")
        if model_name is None:
            raise ValueError(f"Agent '{self.name}' missing model name.")

        self.output_type: Type[Any] = OUTPUT_SCHEMAS.get(
            self.output_schema_name, str
        )

        temp = (
            self.temperature
            if self.temperature is not None
            else global_llm.get("temperature", 0.1)
        )

        chat_model = OpenAIChatModel(model_name)

        self.agent = PydanticAIAgent(
            chat_model,
            instructions=self._build_instructions(),
            output_type=self.output_type,
            model_settings={"temperature": temp},
        )

        logger.info(
            f"Initialized CogniAgent '{self.name}' with model={model_name}, "
            f"output_type={self.output_type}"
        )

    def _build_instructions(self) -> str:
        # Optionally enrich the base prompt with schema hints
        # For simple cases, just return the prompt.
        return self.prompt

    async def invoke(self, input_text: str, context: Dict[str, Any] | None = None) -> Any:
        # `context` can be used later if you want to incorporate more info
        result = await self.agent.run(input_text)
        return result.output

    6.4 Agent Registry¶

    import asyncio
from typing import Dict

from .config_loader import get_agent_configs
from .cogni_agent import CogniAgent

_agents: Dict[str, CogniAgent] = {}
_loaded = False
_lock = asyncio.Lock()


async def ensure_agents_loaded():
    global _loaded
    if _loaded:
        return

    async with _lock:
        if _loaded:
            return

        for cfg in get_agent_configs():
            name = cfg["name"]
            _agents[name] = CogniAgent(cfg)

        _loaded = True


def get_agent(name: str) -> CogniAgent:
    return _agents[name]

    6.5 Workflow Engine¶

    from typing import Any, Dict

from .config_loader import get_workflow_configs, get_template
from .agent_registry import ensure_agents_loaded, get_agent

# workflow configs indexed by name for quick lookup
_workflow_by_name: Dict[str, Dict[str, Any]] = {}


async def load_workflows():
    global _workflow_by_name
    if _workflow_by_name:
        return
    for wf in get_workflow_configs():
        _workflow_by_name[wf["name"]] = wf


async def run_workflow(workflow_name: str, payload: Dict[str, Any]) -> Dict[str, Any]:
    await ensure_agents_loaded()
    await load_workflows()

    wf = _workflow_by_name[workflow_name]
    context: Dict[str, Any] = {"payload": payload, "results": {}}

    for step in wf["steps"]:
        agent_name = step["agent"]
        input_path = step.get("input_from", "payload.content")
        save_as = step.get("save_as", agent_name)

        agent = get_agent(agent_name)
        # resolve input from context via a simple dotted path
        input_text = _resolve_path(context, input_path)

        result = await agent.invoke(input_text, context=context)
        context["results"][save_as] = result

    return context


def _resolve_path(ctx: Dict[str, Any], path: str) -> str:
    parts = path.split(".")
    val: Any = ctx
    for p in parts:
        val = val[p]
    return val


def render_workflow_output(workflow_name: str, context: Dict[str, Any]) -> str:
    template_str = get_template(workflow_name)
    if not template_str:
        # default: return results as a string
        return str(context["results"])

    # Jinja2 environment should be created elsewhere and cached
    from jinja2 import Template
    template = Template(template_str)
    return template.render(**context["results"], payload=context["payload"])

    7. Execution Flow (Example)¶

    1. Caller invokes CogniAgents with:

    2. workflow_name="analyze_text_with_sentiment"

    3. payload={"content": "Some arbitrary text..."}

    4. run_workflow:

    5. Ensures agents & workflows are loaded from config.yaml.

    6. Executes steps:

      • generic_summarizer → results["summary"]
      • sentiment_analyzer → results["sentiment"]

    7. render_workflow_output:

    8. Uses templates.analyze_text_with_sentiment to render final Markdown/HTML.

    Result: a generic, reusable, strongly-typed agentic pipeline that can be applied to any domain, not just news.

    8. OpenWebUI Integration¶

    Environment variables:

    • OPENAI_BASE_URL="http://openwebui:8080/v1"
    • OPENAI_API_KEY="your-token-or-dummy"

    PydanticAI’s OpenAIChatModel(model_name):

    • Sends {"model": "<llm_model from config.yaml>", "messages": [...]} to OPENAI_BASE_URL.
    • OpenWebUI routes the request to the appropriate backend model.

    This makes CogniAgents backend-agnostic as long as the backend speaks OpenAI’s API dialect.

    9. Future Enhancements¶

    • Parallel step execution:

    • Allow parallel: true in workflow steps and run agents concurrently.

    • Tool-using agents:

    • Use PydanticAI tools for external data (APIs, DBs, search).

    • Multi-tenant configs:

    • Support multiple config.yaml files, one per tenant/project.

    • Hot reload in dev:

    • Watch config.yaml and reload agents/workflows on change.

    • Config UI:

    • Build a simple web UI to edit agents, workflows, and templates.

    This design makes CogniAgents a generic, reusable agentic framework that can power everything from your news aggregation use case to code review, support triage, and beyond — all while staying OpenWebUI-compatible and config-driven.
